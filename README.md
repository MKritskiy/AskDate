# AskDate

Сервис для совместного планирования дат и событий. Позволяет создавать группы, отмечать удобные дни в календаре и координировать встречи с участниками.

## Технологии

- **Backend**: .NET 8/10 (ASP.NET Core) — два микросервиса
- **Realtime**: SignalR (WebSocket) — мгновенная синхронизация событий, комментариев и участников
- **Frontend**: Vanilla JS SPA (FullCalendar 6, SignalR client)
- **База данных**: PostgreSQL 16 + EF Core
- **Инфраструктура**: Docker Compose, nginx, GitHub Actions CI/CD

## Запуск

### Локальная разработка

```bash
# Клонирование
git clone https://github.com/MKritskiy/AskDate.git
cd AskDate
git checkout develop

# Запуск через Docker Compose
docker compose up --build
```

Приложение будет доступно на **http://localhost:80**.

### Production

```bash
docker compose -f docker-compose.prod.yml up -d
```

Образы тянутся из Docker Hub. Watchtower автоматически обновляет контейнеры при появлении новых образов.

#### Обновление версии на сервере

Watchtower обновляет только образы. Для изменений в `nginx.conf` и переменных окружения
(`docker-compose.prod.yml`) один раз после git pull выполните:

```bash
git pull
docker compose -f docker-compose.prod.yml up -d   # пересоздаёт контейнеры с новым env и nginx
```

- Миграции БД применяются автоматически при старте. `AddAvailabilityMarks` (2.2) только переименовывает и
  конвертирует колонку `Participants.AvailabilityMode` на месте (`1 → true`) и создаёт таблицу отметок —
  существующие данные не затрагиваются.
- Чтобы выдать права администратора на сервере с существующей БД, задайте `ADMIN_EMAIL=ваш@email`
  в `.env` и пересоздайте контейнер users.web — роль выставится при старте.

### Переменные окружения

Создайте `.env` файл (см. `.env.example`):

```env
DB_PASSWORD=your_secure_password
JWT_KEY=your_jwt_secret_key
JWT_ISSUER=AskDateIssuer
JWT_AUDIENCE=AskDateAudience
DOCKERHUB_USERNAME=your_dockerhub_username
# Email'ы (через запятую), получающие роль Administrator при старте users.web.
# Безопасный способ выдать админа на сервере с уже существующей БД:
ADMIN_EMAIL=you@example.com
# Общий секрет межсервисных вызовов (одинаковое значение для обоих сервисов)
INTERNAL_API_KEY=change_me_random_string
```

## Возможности

- **Группы** — создание и вступление только по пригласительной ссылке (включая QR-код); данные группы доступны лишь её участникам
- **Отметки доступности** — личные отметки двух типов, которые видны всей группе:
  «свободен» (зелёный) и «занят» (красный). Отметка — это весь день или интервал («занят 9:00–12:00»),
  в дне их может быть несколько; пересечения приводятся в порядок автоматически. Тип хранится в отметке,
  поэтому смена инструмента никогда не перекрашивает уже отмеченные дни
- **Инструменты календаря** — «Просмотр» (клик открывает день) и кисти «Свободен» / «Занят»: клик или протяжка
  по диапазону ставит отметку сразу (весь день или заданный интервал времени). Жест, начатый на своей отметке
  того же типа, стирает её и те отметки, по которым он прошёл, — так же массово, как они ставились
- **Панель дня** — мои отметки дня с правкой времени, окно, когда свободны все, и расписание каждого участника
- **Сводка для группы** — полоса внизу дня изображает сутки: зелёным — в это время свободны все, красным — кто-то занят,
  серым — не все отметили; дни с общим окном обведены рамкой. Для тех, кто свободен «всегда, кроме…», есть переключатель
  «Неотмеченные дни считать свободными». У события показывается, кто занят именно на его время
- **События** — отдельная сущность: разовые и регулярные, с названием, временем, участниками и комментариями.
  События не считаются занятостью: встреча в 19:30 не делает весь день занятым
- **Realtime** — изменения событий, комментариев, отметок и участников приходят по WebSocket (SignalR) мгновенно
- **Предстоящие события** — вкладка со списком ближайших событий и поиском
- **Экспорт iCal** — календарь группы в Google/Outlook/Apple Calendar
- **Статистика**, **копирование сводки дня текстом**, **горячие клавиши** (`1`/`2`/`3` — инструменты, `←`/`→` — дни, `Esc`)
- **Авторизация** — JWT + refresh-токены, автоматическое продление сессии
- **Админ-панель** — управление пользователями и сброс паролей
- **Локализация** — русский и английский языки

## Отметки доступности: API и правила

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/groups/{groupId}/availability` | все отметки участников группы |
| PUT | `/api/groups/{groupId}/availability` | `{ dates, type, startTime?, endTime?, replaceIds? }` — ставит отметку на каждый день; с `erase: true` — стирает её с этих дней вместо этого; ответ — отметки автора на этих днях уже после нормализации |
| DELETE | `/api/groups/{groupId}/availability` | `{ ids }` или `{ dates }` — снять свои отметки |
| DELETE | `/api/groups/{groupId}/availability/all` | снять все свои отметки в группе |
| PUT | `/api/groups/{groupId}/availability-default` | `{ unmarkedDaysFree }` — «неотмеченное время считается свободным» |

- `type`: `1` — свободен, `2` — занят. Без `startTime`/`endTime` — весь день; с ними — интервал `HH:mm`;
  конец `24:00` (или `23:59`) — до конца дня.
- Отметки одного участника в дне не пересекаются: сервер склеивает соседние одного типа и даёт новой отметке
  перекрыть противоположную. Стирание (`erase`) убирает только отметки того же типа в указанной области:
  отметка, разрезанная посередине, остаётся двумя частями. Нормализация (`AvailabilityDay`) и расчёт общих окон
  (`computeAvailability` в `app.js`) устроены одинаково — на поминутной линии дня.
- Для группы «занят» важнее «свободен», «свободен» важнее «не отметил»: состояние группы в каждую минуту —
  худшее из состояний участников.

## Проверки перед публикацией

```bash
dotnet build AskDate.slnx -c Release          # сборка
node tools/check-frontend.mjs                 # синтаксис, локализация ru/en, id/обработчики/CSS, рекурсия, эмодзи
docker compose up -d --build                  # локальный стенд
node smoke-test.mjs                           # ~80 проверок API: права доступа, отметки и интервалы, события, админ, SignalR
```

`smoke-test.mjs` создаёт собственные тестовые аккаунты и группу и не трогает остальные данные.

## CI/CD

- **`develop`** — ветка разработки
- **`main`** — продакшен, автоматически собирается через GitHub Actions
- Docker-образы публикуются в Docker Hub: `askdate-web`, `users-web`
- Watchtower на сервере подхватывает обновления каждые 60 секунд
